# mlx-smolvla v0.1.2

Fixes PyPI documentation links and training imports that could fail when your
working directory contains a package named `training` or `reference`.

- The wheel now exposes one top-level package, `mlx_smolvla`. Private lab
  imports live under `mlx_smolvla._lab`; source provenance paths are preserved.
- Runtime dependencies use bounded ranges. The exact lockfile versions, tested
  MLX 0.32.0–0.32.2 support, and strict CPU fallback remain intact.
- `doctor` reports the selected CPU backend and explains native-loader failures.
  Lazy public imports preserve training-worker environment sanitation.
- README links point to this release tag, installation instructions are current,
  and the LeRobot fine-tuning example follows the pinned upstream tutorial.
- The hardware record retains the inconclusive reduced-torque attempt and its
  unmet return check; no sustained motion or task success is claimed.
- Hosted packaging CI and a gated Trusted Publishing workflow are included.
  This release uses the existing local publishing credential; PyPI publisher
  registration remains pending account-password confirmation.

The source distribution and Python 3.11/3.12/3.13 macOS 14+ arm64 wheels are
included. Numerical thresholds and historical result records are unchanged.
